# 百草园 · 产品形态

## 定位

一本开源的中文植物与真菌图鉴，回答三个问题：**这是什么、能不能吃、怎么处理**。延伸到怎么种、哪里有、和什么容易搞混。

| 做 | 不做 |
|---|---|
| 按部位给出安全结论和处理方法，每条结论带出处 | 拍照识别后直接下"可食"结论 |
| 先做好桌面 Web，再做手机 | 医疗建议、剂量、偏方 |
| 数据集和网站同时发布，数据可单独下载使用 | 用户发帖、点赞、社交 |

## 先后

**先做 Web 的桌面宽度，手机宽度和离线放到后面。**

- 第一阶段的主要工作是把数据做对：清洗、对齐、审核。桌面上表格、出处、图谱都摊得开，核对起来方便；这个阶段最需要的读者也是坐在电脑前查资料、核对内容的人。
- 手机上的野外场景依赖离线包和安全审核，两样都要等数据稳定后才能做。
- 只有一个站点，不分两套代码。页面从一开始就用流式布局，在手机上能打开、不错位，但第一阶段不为手机专门设计交互。

## 场景

前五行是先做的；后两行需要手机和离线，后做。

| 场景 | 人在哪里 | 问题 | 入口 | 约束 |
|---|---|---|---|---|
| 查一种植物 | 桌面 | 这是什么？能吃吗？哪个部位？怎么处理？ | 搜索 → 物种页 | 结论在首屏，出处可点 |
| 出发之前 | 桌面 | 这个月、这个省有什么可采？哪些毒蘑菇高发？ | 此时此地 | 按省、按月 |
| 想种点什么 | 桌面 | 现在种什么？怎么种？ | 时令、栽培 | 按气候区 |
| 查药材 | 桌面 | 这味药是哪种植物的哪个部位？ | 药材页 ↔ 物种页 | 与 baicao-knowledge 互通 |
| 翻着看、核对 | 桌面 | 这一科还有什么？它们有什么关系？这条结论出处对吗？ | 分类浏览、图谱、出处 | 表格和出处摊得开 |
| 野外遇见 | 山里，手机，常无信号 | 这是什么？能吃吗？ | 搜索、特征检索 | 离线、单手、结论在首屏 |
| 可能误食 | 任何地方，很急 | 会怎样？现在做什么？ | 急救页 | 一屏、离线、可直接拨号 |

## 结构

```
首页 ─┬─ 搜索（中文名 / 别名 / 拼音 / 学名）
      ├─ 此时此地（省 × 月）── 当季可采 · 当季可种 · 当季高发毒蘑菇
      ├─ 特征检索 ── 类型 · 生境 · 花色 · 叶 · 果 · 菌盖 · 菌褶 …
      ├─ 专题 ── 毒蘑菇 · 有毒植物 · 野菜 · 蔬菜 · 药食同源 · 救荒本草
      ├─ 分类浏览 ── 科 → 属 → 种
      └─ 图谱

物种页 ── 对照页（与易混淆物种并排）
药材页 ── 基原物种 + 部位
急救页
关于 ── 数据来源 · 许可 · 贡献
```

## 物种页

结论在最上面，证据在最下面，中间按"人会问的顺序"排。

桌面宽度分两栏：主栏是名称、安全结论、图片、**各部位的表格**、易混淆、怎么认、怎么种、古籍引文、出处；侧栏是科属与生活型、月历、关系、本页数据的下载。窄屏时侧栏排到主栏下面，表格横向滚动。下面的线框是窄屏时的顺序。

## 安全表达

安全等级挂在**部位**上。物种页顶部显示各部位里最严的一档，再点明可食的部位。

| 等级 | 含义 | 例 |
|---|---|---|
| ● 可食 | 有可靠的食用记录，且该部位无毒性记录 | 马齿苋嫩茎叶 |
| ◐ 处理后可食 | 必须经过指定处理 | 木薯、白果、鲜黄花菜 |
| ◑ 少量 | 过量有害，或对部分人群有害 | 苦杏仁、肉豆蔻 |
| ▲ 有毒 | 会中毒 | 番茄茎叶、发芽马铃薯、大青褶伞 |
| ✕ 致命 | 有致死记录 | 钩吻、乌头、致命鹅膏 |
| ○ 未知 | 没有足够证据 | 页面上写"不要吃" |

等级用形状和文字区分，不只靠颜色。

合并规则：

1. **取最严**。任何一个来源记载有毒，就按有毒显示，并列出持相反说法的来源。
2. **"有食用记录"不等于"可食"**。实测 WCFP 把钩吻（断肠草）标成了食用植物，因为某处文献记载过食用。食用标记只能把"未知"升到"有食用记录"，要升到"可食"还需要该部位没有毒性记录，并且通过人工审核。
3. **未知按不可食显示**，不留白。
4. 安全相关的字段不显示未经审核的机器抽取结果。

## 可信度

每条事实都带出处，页面上能点开。

| 级别 | 条件 | 显示 |
|---|---|---|
| 已审核 | 至少两个独立来源一致，人工看过 | 正常显示 |
| 单一来源 | 一个可靠来源 | 标"单一来源" |
| 待审核 | 机器抽取，没人看过 | 灰色；安全字段不显示 |

来源之间有冲突时，把冲突摆出来，不替读者抹平。

## 对照页

最容易出事的是认错。把一对易混淆物种并排放，逐项比较。

```
            大青褶伞  ▲ 有毒     │  高大环柄菇  ● 可食
  孢子印    绿色                 │  白色                ← 区分点高亮，排在前面
  成熟菌褶  变青绿色             │  保持白色
  菌柄      光滑                 │  有蛇皮状鳞纹
  菌盖      白色，褐色鳞片       │  污白色，褐色鳞片    ← 相同或相近的排在后面
  菌环      有，可移动           │  有，可移动
```

第一批对照页从疾控中心蘑菇中毒年报里"误采"最多的组合做起。

## 此时此地

选省份和月份，得到三张清单：当季可采、当季可种、当季高发毒蘑菇。省份和月份记在本地，下次打开直接是它。

数据来自：WCVP 与 GBIF 的分布；物候与采收期；蘑菇中毒年报里的时间、地区分布。

## 拍照识别

拍一张照片，得到几个候选物种和相似度，每个候选带本站的安全等级，点进去是物种页。只给候选，不给"能不能吃"的结论。

识别由 Pl@ntNet API 完成，只认植物；蘑菇不做拍照识别。照片在浏览器里缩小、重新编码后经 Worker 转给 Pl@ntNet，本站不保存。Pl@ntNet 的免费额度是每天 500 次，所以每个访客每天 20 次，全站每天 480 次。

## 特征检索

不靠照片，靠看得见的特征缩小范围：选几个看得见的特征，剩下的候选越来越少，每个候选都带安全等级。

| | 能用的结构化数据 |
|---|---|
| 植物 | 生活型（WCVP）、省份（WCVP、GBIF）、花色与果实类型（Wikidata，较稀疏） |
| 蘑菇 | 菌盖形状、菌褶着生、菌柄、孢子印颜色、生态类型（Wikidata P783–P788、Mycomorphbox，较完整） |

蘑菇的特征数据比植物好，这个功能先在蘑菇上做。植物的叶形、叶序等特征需要从描述文本里抽取，放到后面。

## 离线（后做）

山里没有信号，手机场景必须能离线。

- 网站是静态的，做成可安装的 PWA。
- 按省份打离线包：该省有分布的物种的文字、缩略图、对照页、急救页。
- 急救页和毒蘑菇专题随应用外壳一起缓存，不依赖离线包。

## 数据即产品

网站只是数据的一种读法。同一份数据同时发布为：

| 形式 | 给谁 |
|---|---|
| Parquet（实体表、关系表、证据表），发布在 Hugging Face | 研究、训练、二次开发 |
| 每个物种一个静态 JSON | 别的应用直接调用，不需要服务器 |
| 仓库里的 YAML 词条 | 贡献者直接改 |

每条记录带 `source` 和 `license`，下游可以按许可证筛选。

## 贡献

- 词条是仓库里的文件，改动走 Pull Request。
- 页面上每个字段旁有"纠错"，跳到预填好的 issue。
- CI 检查：安全字段必须有出处；图片必须有作者和许可；不接受 NC、ND 许可的内容。
- 安全等级的改动需要两个人审核。

## 技术形态

| | 选择 | 原因 |
|---|---|---|
| 站点 | Astro，部署在 Cloudflare Workers | 首页、专题、分类预渲染成静态文件；物种页由 Worker 按需渲染 |
| 物种数据 | Cloudflare D1，一个物种一行 JSON；渲染结果进边缘缓存 | 改一条数据不用重新部署；以后的"此时此地"、特征检索需要查询 |
| 检索 | 浏览器内索引（自建，一个静态文件） | 不需要服务器，离线可用；支持别名、拼音、学名 |
| 图谱 | Cytoscape.js，按物种取子图 | 全图太大，只在物种页显示一跳、两跳 |
| 数据管线 | Python + DuckDB → Parquet | 与 baicao-knowledge 的结构一致 |
| 图片 | 只存链接，直接引用源站（Wikimedia Commons、iNaturalist），页面上标作者与许可 | 见下 |

物种页不预渲染的原因：Cloudflare 免费额度每个 Worker 最多 2 万个静态文件，物种有 3.8 万个。静态文件请求不限量；Worker 每天 10 万次请求，只有物种页用到。

D1 免费额度每天读 500 万行、写 10 万行，全账号共用。所以物种数据不拆表，同步时比对哈希、只写有变化的行。

检索没有用 Pagefind：它对中文在建索引时分词，查询时不分词，搜"马齿苋"这样的整词不可靠；物种名很短，直接做名称索引更合适，还能支持拼音。

公开的资源不必由本项目托管：图片记录的是源站的链接，页面直接引用，不转存。只收开放许可（CC0、公有领域、CC BY、CC BY-SA）的图片，标出作者、许可，并链接回原页面。图片加载失败时物种页不显示图片区。
