# 百草园 · 产品形态

## 定位

一本开源的中文植物与真菌图鉴，回答三个问题：**这是什么、能不能吃、怎么处理**。延伸到怎么种、哪里有、和什么容易搞混。

读者在世界各地，现在只做中文，不做多语言。新功能不默认读者在中国大陆：比如急救电话按地区给。

| 做 | 不做 |
|---|---|
| 按部位给出安全结论和处理方法，每条结论带出处 | 拍照识别后直接下"可食"结论 |
| 网站和 App 共用数据和判断逻辑 | 医疗建议、剂量、偏方 |
| 数据集和网站同时发布，数据可单独下载使用 | 用户发帖、点赞、社交 |

## 先后

**先做 Web 的桌面宽度；手机先做不等数据的部分，离线包放到后面。**

- 第一阶段的主要工作是把数据做对：清洗、对齐、审核。桌面上表格、出处、图谱都摊得开，核对起来方便；这个阶段最需要的读者也是坐在电脑前查资料、核对内容的人。
- 手机上不等数据的部分已经做了：底栏导航、急救页、特征检索、能离线打开的应用外壳。
- App 用 React Native（Expo），先出安卓。页面和网站手机宽度的五个入口一样，数据直接取网站的，判断逻辑和网站共用一份代码。
- 野外辨认要等安全审核和对照页的数据，按地区的离线包也放到后面。
- 网站只有一个，不分桌面版和手机版。页面用流式布局，窄屏时页头只留站名和搜索，底部固定五个入口。

## 场景

前五行在桌面上做。后两行在手机上：急救页没有网络也能用，搜索和特征检索联网用过一次后也能，物种页的离线要等离线包。

| 场景 | 人在哪里 | 问题 | 入口 | 约束 |
|---|---|---|---|---|
| 查一种植物 | 桌面 | 这是什么？能吃吗？哪个部位？怎么处理？ | 搜索 → 物种页 | 结论在首屏，出处可点 |
| 出发之前 | 桌面 | 这个月、这个省有什么可采？哪些毒蘑菇高发？ | 此时此地 | 按省、按月 |
| 想种点什么 | 桌面 | 现在种什么？怎么种？ | 时令、栽培 | 按气候区 |
| 查药材 | 桌面 | 这味药是哪种植物的哪个部位？ | 药材页 ↔ 物种页 | 与 baicao-knowledge 互通 |
| 翻着看、核对 | 桌面 | 这一科还有什么？它们有什么关系？这条结论出处对吗？ | 分类浏览、图谱、出处 | 表格和出处摊得开 |
| 野外遇见 | 山里，手机，常无信号 | 这是什么？能吃吗？ | 搜索、特征检索 | 离线、单手、结论在首屏 |
| 可能误食 | 任何地方，很急 | 会怎样？现在做什么？ | 急救页 | 一屏、离线、可直接拨号 |

## 结构

```
首页 ─┬─ 搜索（中文名 / 别名 / 拼音 / 学名）
      ├─ 此时此地（省 × 月）── 当季可采 · 当季可种 · 当季高发毒蘑菇
      ├─ 特征检索 ─┬─ 植物：生活型 · 气候 · 在中国哪里有
      │            └─ 蘑菇：子实层 · 孢子印 · 菌环 · 菌托 · 菌褶着生
      ├─ 专题 ── 毒蘑菇 · 有毒植物 · 野菜 · 蔬菜 · 药食同源 · 救荒本草
      ├─ 分类浏览 ── 科 → 属 → 种
      └─ 图谱

物种页 ── 对照页（与易混淆物种并排）
药材页 ── 基原物种 + 部位
急救页 ── 有毒物种页、危险专题、页脚、手机底栏都能进
关于 ── 数据来源 · 许可 · 贡献
```

手机宽度底部固定五个入口：首页、识别、检索、专题、急救。

## 物种页

结论在最上面，证据在最下面，中间按"人会问的顺序"排。

桌面宽度分两栏：主栏是名称、安全结论、图片、**各部位的表格**、易混淆、怎么认、怎么种、古籍引文、出处；侧栏是科属与生活型、月历、关系、本页数据的下载。窄屏时侧栏排到主栏下面，表格横向滚动。下面的线框是窄屏时的顺序。

## 安全表达

安全等级挂在**部位**上。常见食物的顶部结论只说平常吃的部位，比如番茄只说果实；其余物种顶部显示各部位里最严的一档。

| 等级 | 含义 | 例 |
|---|---|---|
| ● 可食 | 有可靠的食用记录，且该部位无毒性记录 | 马齿苋嫩茎叶 |
| ◐ 处理后可食 | 必须经过指定处理 | 木薯、白果、鲜黄花菜 |
| ◑ 少量 | 过量有害，或对部分人群有害 | 苦杏仁、肉豆蔻 |
| ▲ 有毒 | 会中毒 | 番茄茎叶、发芽马铃薯、大青褶伞 |
| ✕ 致命 | 有致死记录 | 钩吻、乌头、致命鹅膏 |
| ○ 未知 | 没有足够证据 | 页面上写"不要吃" |

等级用形状和文字区分，不只靠颜色。

合并规则：

1. **取最严**。任何一个来源记载有毒，就按有毒显示，并列出持相反说法的来源。常见食物除外，见第 5 条。
2. **"有食用记录"不等于"可食"**。实测 WCFP 把钩吻（断肠草）标成了食用植物，因为某处文献记载过食用。食用标记只能把"未知"升到"有食用记录"，要升到"可食"还需要该部位没有毒性记录，并且通过人工审核。
3. **未知按不可食显示**，不留白。
4. 安全相关的字段不显示未经审核的机器抽取结果。
5. **常见食物看平常吃的部位**。日常吃的蔬菜、水果、粮食、调料和栽培菇类列在 `data/reviewed/foods.csv`，一行是一个审核过的食用部位：可食、处理后可食或少量，加一句必要的提醒（"必须煮熟""发苦的不要吃"），`source` 列写依据。这些物种顶部只说这个部位；其他部位有等级的毒性记录列在部位表里，用途记录和文献不再列出。野菜按 [#10](https://github.com/ticoAg/baicaoyuan/issues/10) 的清单，逐条查到可信来源后再加进这张表。

## 可信度

每条事实都带出处，页面上能点开。

| 级别 | 条件 | 显示 |
|---|---|---|
| 已审核 | 至少两个独立来源一致，人工看过 | 正常显示 |
| 单一来源 | 一个可靠来源 | 标"单一来源" |
| 待审核 | 机器抽取，没人看过 | 灰色；安全字段不显示 |

来源之间有冲突时，把冲突摆出来，不替读者抹平。

## 对照页

最容易出事的是认错。把一对易混淆物种并排放，逐项比较。

```
            大青褶伞  ▲ 有毒     │  高大环柄菇  ● 可食
  孢子印    绿色                 │  白色                ← 区分点高亮，排在前面
  成熟菌褶  变青绿色             │  保持白色
  菌柄      光滑                 │  有蛇皮状鳞纹
  菌盖      白色，褐色鳞片       │  污白色，褐色鳞片    ← 相同或相近的排在后面
  菌环      有，可移动           │  有，可移动
```

第一批对照页从疾控中心蘑菇中毒年报里"误采"最多的组合做起。

## 此时此地

选地区（中国按省份）和月份，得到三张清单：当季可采、当季可种、当季高发毒蘑菇。地区和月份记在本机，下次打开直接是它。

数据来自：WCVP 与 GBIF 的分布；物候与采收期；蘑菇中毒年报里的时间、地区分布。

## 维护后台

维护者登录后直接在线上改：新建词条，改中文名和别名，改类型与科属，上传图片（一个词条可以有多张）。改动单独存放，不随数据管线的更新丢失；安全结论不在后台改。

申请成为维护者只要一个名字和一个密码，管理员通过后就能登录。上传的照片署上传者的名字，按 CC BY 4.0 公开。每次改动记下是谁改的；管理员可以撤销改动、移除维护者。

## 拍照识别

拍一张照片，得到几个候选物种和相似度，每个候选带本站的安全等级，点进去是物种页。只给候选，不给"能不能吃"的结论。

识别由 Pl@ntNet API 完成，只认植物；蘑菇不做拍照识别。照片在浏览器里缩小、重新编码后经 Worker 转给 Pl@ntNet，本站不保存。Pl@ntNet 的免费额度是每天 500 次，所以每个访客每天 20 次，全站每天 480 次。

## 急救页

疑似误食时打开的一页（`/aid/`），一屏看完，能直接拨号。

- 最上面是急救电话的大按钮。地区按时区猜，可以改，改过的记在本机。美国、英国、澳大利亚、新西兰多一个中毒咨询号码。猜不出地区时不给号码，只写"拨打当地的急救电话"。
- 下面六条：马上打电话或去医院，没有症状也去；带上吃剩的，没有就拍照；一起吃过的人一起去；记下时间和分量；不吃喝、不自己催吐，土法验毒解毒都没用；吐泻好了不等于没事。
- 每条都对得上公开的指引，页面上列出：新南威尔士州卫生厅的中文页、NHS、默沙东诊疗手册、新华社关于"假愈期"的报道。不写剂量和偏方。
- 入口：有毒、致命、可能有毒的物种页，危险专题页，页脚，手机底栏。

## 特征检索

不靠照片，靠看得见的特征缩小范围：先选植物还是蘑菇，再选几个特征，剩下的候选越来越少，每个候选都带安全等级。网站是 `/finder/`，App 是底栏的"检索"，两边一套规则。

| | 能用的结构化数据 |
|---|---|
| 植物 | 生活型、气候（WCVP）、省份（WCVP、GBIF）、花色与果实类型（Wikidata，较稀疏） |
| 蘑菇 | 菌盖形状、菌褶着生、菌柄、孢子印颜色、生态类型（Wikidata P783–P788、Mycomorphbox，较完整） |

现在用的：

| | 特征 | 有记录 |
|---|---|---|
| 植物 | 生活型、气候、在中国哪里有（十个大区） | 37,380 种 |
| 蘑菇 | 子实层、孢子印颜色、菌环、菌托、菌褶着生 | 434 种 |

植物这三项只能把范围缩到几百、几千种；叶形、叶序、花色要从描述文本里抽取，放到后面。蘑菇不用菌盖形状（随菌龄变）和生态类型（肉眼看不出）。

规则：

- 同一项里多选是"或"，不同项之间是"且"。数据里的写法归到几个选项上，一种可以归到几个：攀援灌木既算灌木也算藤本，介于两色之间的孢子印两边都算（赭色算黄也算褐），宁可多留候选。
- 某项没有记录的种类不排除，列进"无法排除"。只选了"没看到"菌环或菌托时，有的种类也只放进"无法排除"：菌环会脱落，菌托常埋在土里。
- 不能按安全等级筛：没有毒性记录不等于能吃。候选按危险程度排序；候选里有致命种类时，在最上面列出名字。
- 每段先列 100 种，可以接着往下列。
- 特征码写在搜索索引里，和搜索共用一个文件，不另外下载。

## 离线

山里没有信号，手机场景必须能离线。

- 网站可以加到主屏幕（PWA）。service worker 缓存应用外壳：急救页、特征检索、毒蘑菇专题和一个离线提示页；搜索索引联网时照常下载，存一份，断网时用存的。其他页面断网时显示离线提示。
- App 的急救内容打包在安装包里。搜索索引（特征检索也用它）、专题、看过的物种页下载一次后存在本机，没网时用旧的。图片不存。
- 按地区打离线包（该地区有分布的物种的文字、缩略图、对照页）先不做。

## 数据即产品

网站只是数据的一种读法。同一份数据同时发布为：

| 形式 | 给谁 |
|---|---|
| Parquet（实体表、关系表、证据表），发布在 Hugging Face | 研究、训练、二次开发 |
| 每个物种一个静态 JSON | 别的应用直接调用，不需要服务器 |
| 仓库里的 YAML 词条 | 贡献者直接改 |

每条记录带 `source` 和 `license`，下游可以按许可证筛选。

## 贡献

- 词条是仓库里的文件，改动走 Pull Request。
- 页面上每个字段旁有"纠错"，跳到预填好的 issue。
- CI 检查：安全字段必须有出处；图片必须有作者和许可；不接受 NC、ND 许可的内容。
- 安全等级的改动需要两个人审核。

## 技术形态

| | 选择 | 原因 |
|---|---|---|
| 站点 | Astro，部署在 Cloudflare Workers | 首页、专题、分类预渲染成静态文件；物种页由 Worker 按需渲染 |
| App | React Native（Expo），先出安卓；推送版本 tag 时构建 APK，发布到 GitHub Releases | 一套代码出安卓和 iOS；搜索、特征检索、安全结论、急救电话的代码在 `web/src/lib/`，和网站共用 |
| 物种数据 | Cloudflare D1，一个物种一行 JSON；渲染结果进边缘缓存 | 改一条数据不用重新部署；以后的"此时此地"需要查询 |
| 检索 | 浏览器内索引（自建，一个静态文件） | 不需要服务器；支持别名、拼音、学名 |
| 离线 | service worker，构建时生成 | 只缓存急救等几页和搜索索引，不缓存物种页和图片 |
| 图谱 | Cytoscape.js，按物种取子图 | 全图太大，只在物种页显示一跳、两跳 |
| 数据管线 | Python + DuckDB → Parquet | 与 baicao-knowledge 的结构一致 |
| 图片 | 数据里的图只存链接，直接引用源站（Wikimedia Commons、iNaturalist）；后台上传的图存 R2。页面上标作者与许可 | 见下 |

物种页不预渲染的原因：Cloudflare 免费额度每个 Worker 最多 2 万个静态文件，物种有 3.8 万个。静态文件请求不限量；Worker 每天 10 万次请求，只有物种页用到。

D1 免费额度每天读 500 万行、写 10 万行，全账号共用。所以物种数据不拆表，同步时比对哈希、只写有变化的行。

检索没有用 Pagefind：它对中文在建索引时分词，查询时不分词，搜"马齿苋"这样的整词不可靠；物种名很短，直接做名称索引更合适，还能支持拼音。

公开的资源不必由本项目托管：图片记录的是源站的链接，页面直接引用，不转存。只收开放许可（CC0、公有领域、CC BY、CC BY-SA）的图片，标出作者、许可，并链接回原页面。图片加载失败时物种页不显示图片区。后台上传的照片是例外，存在本项目的 R2 里，同样要写作者和许可。
